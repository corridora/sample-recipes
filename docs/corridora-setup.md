# Set up Corridora for The Recipe Table

Published 2026-10-11 · Updated 2026-10-11

## 1. Choose your destination and create credentials

Contributors use their own Corridora organization by default. Create a project
containing `sample-recipes-web`, `sample-recipes-api`,
`sample-recipes-enrichment`, and `sample-recipes-gcp-adapter`. Use the namespace
`corridora-samples.recipes` and the environment `development`, or `demo` for the
maintained demo deployment. Resource attributes do not create projects/services.

Create a browser RUM application/key for `sample-recipes-web`, and a scoped backend
ingest key for the three Python producers. They must route to the same tenant.
The browser key is intentionally public; the backend key stays in server secrets.
A management/query credential is a separate capability and is never embedded in
the app or sent to dependencies.

For maintained Demo, an authorized Corridora operator supplies the two keys.
Canonical Demo UUID: `00000000-0000-4000-8000-000000000201`. The key controls routing;
the application does not add a tenant UUID to override it or mint keys through a
public demo persona. The standard base endpoint is `https://ingest.corridora.com`.

## 2. Run the setup wizard

```sh
./setup configure
./setup deploy
./setup run
```

The following prompts map to the files generated by setup. Nonsecret answers live
in `.sample/config.json`; credentials live in `.sample/secrets.json`. Both are
ignored by Git and owner-readable/writable, with an owner-only state directory.
Secret prompts are masked. Never paste account passwords into setup.

| Prompt / variable | Meaning and default |
| --- | --- |
| `SAMPLE_MODE` | `local` uses SQLite/fixtures; `cloud` uses GCP clients. |
| `CORRIDORA_TARGET` | `own` by default; `demo` requires operator keys and forces the demo environment prompt. |
| `CORRIDORA_OTLP_ENDPOINT` | Ingest base URL; setup/runtime append `/v1/traces`, `/v1/logs`, `/v1/metrics`. |
| `CORRIDORA_RUM_SCRIPT_URL` | Hosted RUM distribution, default `https://rum.corridora.com/corridora-rum.js`. |
| `CORRIDORA_RUM_KEY` | Visible browser RUM credential. Blank disables local RUM. |
| `CORRIDORA_INGEST_KEY` | Backend `X-CORRIDORA-KEY`; blank disables local export. Required in cloud. |
| `OTEL_SERVICE_NAME`, `OTEL_SERVICE_NAMESPACE` | Stable API identity and namespace. Worker/adapter use the fixed names above. |
| `DEPLOYMENT_ENVIRONMENT` | `development` locally; `demo` for maintained Demo. |
| `RESOURCE_PREFIX` | 3–23 lowercase letters/digits/hyphens; choose a dedicated unique prefix. |
| `PORT` | Local port, default 4103. Cloud listens on 8080. |
| `DEMO_DAILY_START_UTC`, `DEMO_WINDOW_SECONDS` | `13:40`, 600 seconds. All handlers reevaluate daily/override expiry. |
| `DEMO_CONTROL_TOKEN` | Automatically generated dedicated secret; use this same value in the protected browser-runner secret. |
| `ENABLE_PROVIDER_FORWARDING` | `false` initially; `true` creates the bounded native Logging/Monitoring paths. |
| `ENABLE_SYNTHETICS` | Saved intent; configure the GitHub variables/secret below to activate the hosted browser runner. |
| `REVIEW_SUMMARY_URL` | Controlled AWS origin, or exact `/internal/review-summary` endpoint. Empty uses the fixture. |
| `DOWNSTREAM_AUTH_TOKEN` | Optional dedicated dependency bearer credential; unrelated to ingest/control keys. |
| `GCP_PROJECT`, `GCP_REGION` | Existing billing-enabled project and `us-central1`. |
| `FIRESTORE_DATABASE` | Explicit selected shared database, default `(default)`. |
| `FIRESTORE_CREATE_IF_MISSING` | Default false; explicit true creates a Native database but retains it on teardown. |
| `GCS_BUCKET`, `REUSE_BUCKET` | Globally unique new bucket; explicit existing-bucket reuse is retained. |
| `PUBSUB_TOPIC` | Dedicated enrichment topic, defaults to `<prefix>-enrichment`. |
| `GCP_SERVICE_ACCOUNT`, `PUSH_IDENTITY` | New dedicated app and Pub/Sub/Scheduler identities in the selected project. |
| `PUBLIC_URL` | Local URL or cloud-discovered exact Cloud Run HTTPS origin. |
| `SERVICE_VERSION` | Derived from actual Git commit; before first commit, a content digest identifies the source build. |

For CI, export variables or pass `--config /protected/path/config.json` and
`--non-interactive`; missing required values fail clearly. Example with no secret
values on the command line:

```sh
./setup configure --non-interactive
./setup deploy --plan
./setup deploy --non-interactive --yes
```

`--plan` and `--dry-run` are synonyms. Cloud deployment prints its selected project,
resource inventory, cost assumptions and active account. Rerun it to resume a
partial operation or deploy a changed source build. Keep `.sample/resources.json`
to establish ownership; a matching resource name alone is insufficient for reuse.

## 3. Understand the instrumentation files

- `app/telemetry.py` creates Python SDK TracerProvider, LoggerProvider and
  MeterProvider plus OTLP HTTP protobuf exporters. Exporter timeouts are 1.5 s;
  lifecycle flush uses finite budgets. Export failures are visible in stderr and
  the health response. Exporter requests have no automatic HTTP instrumentation.
- `app/main.py` extracts W3C context before SERVER spans, adds database/storage and
  dependency CLIENT spans, creates Pub/Sub PRODUCER spans and injects their context.
  The consumer extracts message context under `sample-recipes-enrichment` and
  explicitly flushes before returning the push acknowledgment.
- `frontend/index.html` reserves the RUM slot at the top of `<head>`. The server
  injects the configured script before Vue's first request, with URL-encoded `ckid`,
  endpoint, stable identity, actual build, 100% trace sampling, long tasks and exact
  API-origin allowlist. Only the visible RUM key enters the HTML.
- `frontend/src/App.vue` adds manual action spans with `@opentelemetry/api`.
  Fetch begins inside an explicit action context. The RUM distribution owns the
  browser SDK and creates the actual CLIENT spans/injects `traceparent`.

The API serves the built UI on the same origin, so no cross-origin API CORS policy
is needed. The HTML CSP permits only the configured RUM script host and ingest
host alongside self. Corridora ingest must allow the frontend origin and its RUM
headers. Cross-cloud context travels only to the explicitly configured AWS URL,
using HTTPS, a bounded timeout and no redirects. Backend/control keys are never
forwarded to that dependency. Real advertising tags are not enabled in this sample;
use the fleet's controlled tracker simulator for those scenarios.

## 4. Add GCP native signals

Set `ENABLE_PROVIDER_FORWARDING=true` and rerun deploy. The Logging sink exports
10% of this Cloud Run service's native request records to a dedicated Pub/Sub topic.
An authenticated OIDC push invokes `/internal/provider/logs`. The app verifies
issuer/signature/audience and the exact `PUSH_IDENTITY` email, even though the UI
service accepts public requests. The sink writer can publish only to its topic;
the Google-managed Pub/Sub agent can sign for the dedicated push identity.
[Authenticated push](https://docs.cloud.google.com/pubsub/docs/authenticate-push-subscriptions),
[Logging destination permissions](https://docs.cloud.google.com/logging/docs/export/configure_export_v2).

`app/provider.py` preserves native trace/span IDs and source timestamps when
present. Records without source IDs attach a root context, so they never inherit
the adapter's HTTP span. Transactional leases reserve each native log ID before
export and complete only after successful flush; a failed flush returns a retryable
503. Checkpoints suppress recent duplicate push delivery (128 entries/24 hours;
transport acknowledgment ambiguity prevents an exactly-once guarantee). Arbitrary JSON
payloads, URL query strings and credentials are not forwarded. The sink excludes
`/internal/` traffic to avoid recursive platform-log export.

The Scheduler dispatcher polls two native Cloud Run metrics every 15 minutes with
`roles/monitoring.viewer`, at most eight series/four points per metric. The adapter
emits request-count snapshots and latency distribution means with original
interval timestamps as attributes. It does not reconstruct provider spans,
original distribution buckets or a lossless full platform archive. SDK traces for
Firestore/Storage represent client operations; there are no fabricated server-side
Firestore spans. Monitoring can lag. Bounded point checkpoints use native metric,
resource, labels and interval identity to suppress retained overlap; a failed flush
releases reservations and returns a retryable scheduler error.

## 5. Verify the browser and backend together

```sh
./setup verify
```

The Playwright journey performs healthy search/detail/enrichment, activates the
bounded bad revision, observes six sequential reads and 1.5 s delay, opens the
healthy control recipe, and recovers. It prints regression/recovery trace IDs and
writes the day's heartbeat only after all assertions pass.

In Corridora, open a fresh browser session for `sample-recipes-web`. Find its fetch
CLIENT span for `/api/recipes/demo-recipe`, then prove the API SERVER span has the
same trace ID and its `parent_span_id` equals that CLIENT span's ID. Inspect the
AWS leaf when configured. For enrichment, find the PRODUCER and the worker's
CONSUMER with matching trace ID and the correct producer parent. Confirm a
correlated application log, `sample.http.duration`, `sample.enrichment.jobs`, the
simulated deployment event, and a native provider log/metric.

Ingest 200 responses, a manually supplied test trace header, or a browser script
load do not prove stored correlation. This sample does not accept a query credential
or query Corridora automatically; these stored-data checks remain explicit operator
UI work. Offline tests can assert actual RUM correlation using `RUM_BUNDLE_PATH`,
as described in README, with every export captured locally using mock keys.

## 6. Replay, rotate and clean up

```sh
./setup scenario --phase regression --duration 120
./setup scenario --phase recover --duration 120
```

`POST /api/demo/scenario` requires the dedicated control bearer token and an integer
duration 1..600. `healthy`, `regression` and `recover` are accepted. The saved
override expires in every handler and queue delivery; recovery does not rely on a
second timer. Find `event.name=deployment` / `feature_flag`, `demo.simulated=true`,
`demo.scenario=missing-batch-read`, and the unique `demo.release`. Actual
`service.version` identifies the deployed source throughout the simulated change.

For daily browser coverage, configure GitHub variable `APP_URL`, variable
`ENABLE_SYNTHETICS=true`, and secret `DEMO_CONTROL_TOKEN`. The every-15-minute
watchdog replays a real browser incident after 13:50 UTC if today's heartbeat is
missing. GitHub schedule delays and inactive repositories can leave a gap; monitor
the heartbeat from a reliable external runner when a daily guarantee is required.
`BASE_URL=... DEMO_CONTROL_TOKEN=... python scripts/daily.py` is the runner entry
point; supply secrets through the environment, not shell history.

Rotate Corridora keys in the operator UI, rerun `./setup configure`, then deploy.
Cloud backend secrets are mounted from Secret Manager; old active secret versions
are destroyed after replacement. Rotate the independent control/downstream keys
the same way and update the browser-runner secret.

Use `./setup destroy --plan`, then `./setup destroy`. The inventory plus remote
ownership markers gate deletion. Cleanup removes this app's Firestore collection
and object prefix, then dedicated resources. It retains the GCP project, database,
enabled APIs and any reused bucket. Teardown never deletes the recommender or
other cloud dependencies. Local destroy stops only a wizard-owned app process;
it retains ignored configuration for reuse. Stop a foreground `./setup run` with
Ctrl-C.

If no telemetry arrives, check `/healthz` exporter status, key tenant/scopes,
OTLP base URL, browser script 404/CSP/CORS, exact API origin, pending Pub/Sub/DLQ
messages and push audience/email. If cloud startup fails, check Secret Manager
mount permission, Firestore database selection, Cloud Build registry permissions
and whether your organization permits unauthenticated Cloud Run UI access.
